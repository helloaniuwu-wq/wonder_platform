## [19:57] 修复 AI 首席投顾全模型 `Load failed`（上游流式消费 + SSE 心跳保活 + 推理预算调优）

**[Status]** 全量单测与类型检查通过，准备发布 Cloudflare Worker 并推送至 `origin/main`。

**[Root Cause]**
1. `deepseek-v4-pro` 配合 `reasoning_effort: "high"` 非流式耗时超过 120s，触发 Cloudflare / 浏览器长连接空闲超时并丢失 CORS 响应头，浏览器表现为 `TypeError: Load failed`。
2. `qwen/qwen3.7-plus` 与开启思考的 `deepseek-flash` 在 `4096–6144` `max_tokens` 下把配额全部耗尽在 `reasoning`，导致 `content` 为空字符串并触发慢速降级链。

**[Change Log]**
- **上游流式读取与推理预算调优**（`apps/api-worker/src/services/llm.ts`）：
  - 新增 `useUpstreamStream`、`attemptTimeoutMs`、`onProgress` 与 `consumeOpenAiResponse()`，增量消费上游 SSE `data:` 分片并向调用方实时回调 `connecting` / `thinking` / `writing` 状态与字符统计；兼容 `json` / `sse` 双格式与 `AbortController` 超时。
  - 将 `deepseek-v4-pro` 思考强度调优为 `reasoning_effort: "low"`，并将 `deepseek-v4-pro` / `qwen/qwen3.7-plus` `max_tokens` 预算提升至 `16384`；`deepseek-flash` 默认关闭 thinking（`6144` `max_tokens`）以保留完整正文预算与快速响应能力。
- **后端 SSE 流式心跳输出**（`apps/api-worker/src/routes/quant.ts`）：
  - `POST /api/quant/recommend/explain` 当 `stream === true` 或 `Accept` 包含 `text/event-stream` 时返回 `ReadableStream` SSE 响应，每 `2.5s` 发送 `event: progress` 保活，完成后输出 `event: result` 或 `event: error`，并保留 Hono 全局 CORS 响应头；压缩报告字数指导（每节 180–300 字）缩短总体耗时。
- **前端实时进度展示与流式解析**（`apps/fis-hub/src/components/AdvisoryView.jsx`）：
  - `handleGenerateAiAnalysis()` 启用 `stream: true` 增量解析 SSE 事件流并兼容普通 JSON 响应，加载区实时展示已用秒数、当前阶段、推理字数与正文输出字数。
- **单测补强**（`apps/api-worker/src/services/quant.test.ts`、`apps/api-worker/src/routes/fip.auth.test.ts`）：
  - 更新 `deepseek-pro` 预算断言，新增上游 SSE 分片解析与 `POST /api/quant/recommend/explain` 带 `Origin` 的 SSE CORS 响应头验证；`wonder-api-worker` 78/78 PASS、`tsc --noEmit` 0 错误、`fis-hub` 48/48 PASS。
